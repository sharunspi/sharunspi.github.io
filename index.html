Single Responsibility Principle (SRP)

A class should have one, and only one, reason to change. This means it should perform only one job or contain a single focus of logic.

example.py Python 
# Single Responsibility Principle violation
class UserReport:
    def __init__(self, name, email):
        self.name = name
        self.email = email
        
    def generate_report(self):
        return f"User Report: {self.name} ({self.email})"
        
    def save_to_database(self):
        print(f"Saving user {self.name} to database...")
        
    def print_raw_format(self):
        print(f"=== REPORT ===\nName: {self.name}\nEmail: {self.email}\n==============")

Why this matters:

The original class handles three separate concepts: holding user data, persisting to the database, and printing the report. If the database schema changes, or the print layout format changes, this class must be modified. In the refactored version, we extract the printing and database behaviors into their own dedicated classes, making the system modular and testable in isolation.
